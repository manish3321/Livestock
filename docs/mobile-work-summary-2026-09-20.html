Today’s goal: Stabilize and harden the native mobile app — fix runtime API/task errors, improve scan & search UX, audit every screen for real bugs, and ship concrete fixes across shed rounds, inbox deep-links, animals, breeding, health, revenue, and related modules.

1. Database & API — task enum crash

Database Nest API was spamming GET /v1/tasks failures: Value 'ANESTRUS_VET' not found in enum 'TaskType'.

  • Inspected Postgres TaskType enum vs Prisma schema.
  • Remapped legacy rows: ANESTRUS_VET, ANESTRUS_MINERAL, ANESTRUS_DECISION, and other orphan labels → current schema values (e.g. SILENT_HEAT_CHECK, REPEAT_BREEDER).
  • Added migration 20260920143000_remap_legacy_task_types and a one-off remap script.
  • Verified prisma.task.findMany() and smoke-tested mobile-facing endpoints (all 200).

2. Scan & search UX

  • Feature Scan hub — live animal/batch suggestions while typing (280ms debounce), not only on “Find”.
  • Fix UUID / QR payloads resolve via API instead of inventing a fake short tag.
  • Feature AnimalIdSearch — same live typeahead + clear network vs empty-state messaging.
  • Fix Scan overlay no longer advances with a bogus tag when detail fetch fails.
  • UI QR scan FAB icon redesigned: viewfinder corners + QR modules + scan beam (was ID-card glyph).

3. Inbox deep-links & module routing

Task actionPath values like /breeding?form=heat&animalId=… were ignored on mobile (opened Breeding/Health with no tab or animal).

  • Added lib/action-path.ts + unit tests.
  • Wired Inbox open-task → parsed stack destinations.
  • Breeding / Health / Feed / Revenue honor route params (form, type, animalId, breedingId).
  • Breeding PD / calving / colostrum: selecting a record switches tab and shows selection; required animal checks on save.
